# Decisions

One entry per decision: decision — reason — alternatives considered.

- **D-001 App folder `FactoryTwin/` inside the existing AppCreations repo; no nested `git init`.** — The repo is a multi-app collection with its own history; a nested repo would break it. — Separate repository (not possible in this session's scope).
- **D-002 Milestone tags are `m1`…`m7`.** — Requested by the spec and no tags exist yet in the repo. — Prefixed tags (`factory-m1`); would be safer if another app ever adopts milestone tags.
- **D-003 Work on branch `claude/confident-babbage-ybg1uj`.** — Session rule; `main` is never touched, so it can never be broken. — Committing to main.
- **D-004 `.npmrc legacy-peer-deps=true`.** — npm 10.9 arborist crashes (`edgesOut` null) resolving vitest's optional peer set; legacy peer resolution installs cleanly. React-is is listed explicitly for Recharts. — pnpm/yarn (not installed).
- **D-005 Pinned versions: React 19.3, three 0.187, R3F 9.8, drei 10.7, Vite 7.3, Vitest 4.1, TypeScript 5.9, Zustand 5.1, Recharts 3.10, @playwright/test 1.63.** — Latest stable lines compatible with each other; Playwright pinned to the preinstalled browser build. — Vite 8 / TS 7 (newer, less proven toolchain).
- **D-006 `tsx` dev dependency.** — Runs TypeScript scripts (calibration, scenario report) in Node without a build step. — ts-node (slower, ESM friction).
- **D-007 Simulation layer purity enforced by a Vitest test scanning imports and banned globals.** — No extra ESLint toolchain needed and it runs with `npm test`. — ESLint `no-restricted-imports` (extra deps and config).
- **D-008 Scheduled events are data (`type` + ids), not closures.** — Serialisable, hashable, worker-safe, debuggable. — Closure callbacks (simpler, but opaque).
- **D-009 Event log = domain records with a rolling 64-bit FNV-1a hash; full array kept only when requested.** — 30-day runs produce ~1M records; hashing keeps memory flat while still proving determinism. — Always keeping full log.
- **D-010 Calibration via explicit handling times.** — With 3 cells at 90/120 s and 2 inspection stations at 25 s the spec's utilisation targets cannot all hold (inspection would be ~33%). Kept every stated mean and added robot handling (8 s + 7 s per assembly cycle) and inspection handling (20 s per unit). — Changing the stated means or station counts.
- **D-011 Time origin t = 0 is Day 1 06:00 (start of shift 1).** — Production starts immediately on load. — Midnight origin with an idle night first.
- **D-012 Failures sample Weibull residual life on busy/operating time; jobs resume after repair (preempt-resume).** — Idle machines do not wear; wear-out shape > 1 makes preventive maintenance meaningful for the optimizer. — Calendar-time exponential failures.
- **D-013 Units are created when released to a cell (not at order arrival).** — Bounded product count (WIP limit) and the cell assignment is known; unreleased demand lives on the order. — One product per ordered unit at arrival.
- **D-014 Packaging kits are consumed from raw storage at the packaging station (line-side replenishment not modelled).** — Keeps AGV traffic focused on assembly kits; still lets a packaging-kit shortage starve packaging. — Separate AGV deliveries of packaging kits.
- **D-015 Pallets are per order; with all build positions busy, the oldest partial pallet is closed short.** — Avoids palletizer deadlock when orders interleave; real palletizers do the same. — Mixed-order pallets.
- **D-016 Shipping is per order: a carrier is requested when the order is complete in FG.** — Gives order-level ship times and a clear on-time definition. — Scheduled trucks.
- **D-017 Vehicles do not avoid each other on aisles; pick-up/drop-off points have capacity 1 with FIFO queues.** — Spec allows simple queueing; avoids deadlock-prone lane reservations. — Edge reservation.
- **D-018 Main-thread `LocalSimHost` is the default for the live view; `WorkerSimHost` implements the same interface (`?worker=1`) and the optimizer always runs in a worker.** — Lowest latency for selection/detail queries; worker path proves the boundary. — Worker always.
- **D-019 Parallel streams; m1 and m2 tag the same checkpoint.** — The 3D Engineer subagent built models/environment (M1) while the main session built the engine (M2), so both landed before the first verified checkpoint. Later milestones get their own commits. — Serialising the work (slower) or rewriting history to fake separate commits.
- **D-020 Default demand 31 orders/day (12–72 units), materials ROP ≈ 2 days of use.** — Calibration over 30 days: assembly 90–93%, inspection ~50%, packaging 66–69%, assembly is the detected bottleneck; the earlier ROP caused stockouts that hid the real bottleneck. — 27–29 orders/day (assembly 80–84%).
- **D-021 Forklift task priority: store pallets first, urgent put-away when a material is below 35% of its ROP, then truck loading, then routine put-away; aging moves a task up at most one class.** — Under saturated demand static priorities starved put-away and caused stockouts while material sat at the dock; unbounded aging starved the palletizer instead. — Pure FIFO; unbounded aging.
- **D-022 Assembly cell geometry: kit table, fixture and outfeed within 2.1 m of the robot.** — Robot reach is 2.43 m; the first layout put the kit table 3.5 m away. — Bigger robot model.
- **D-023 Products, totes, cartons and pallets are drawn by the sync layer with InstancedMesh (models get cargo=0 / hasCarton=false / totes=0).** — One code path resolves every product's position (also used by follow-camera and selection) and every unit stays clickable. — Letting each model draw its own cargo.
- **D-024 URL state (`?scenario=&t=&paused=&select=&cam=&tab=&perf=`).** — Deterministic screenshots and demos: headless software WebGL runs at ~1 fps, so states are reached by fast-forwarding the engine. — Driving the UI with clicks in Playwright (slow, flaky).
- **D-025 Packaging-kit consumption, robot handling and inspection handling count as busy time.** — Matches what the beacons and the animation show. — Counting only the machine process.
- **D-026 Optimized preset = the optimizer's own #1 result for the growth scenario (budget 60, 3 seeds × 4 days); `npm run report` warns if the preset drifts.** — "Improved throughput after optimization" must be the optimizer's output, not a hand-picked configuration (a hand-picked 4-cell/3-AGV config scored better, showing hill climbing is path dependent; documented as a limitation). — Hand-tuned preset.
- **D-027 Major-breakdown preset = Cell 2 down 10 h + C2 down 90 min.** — A 4 h outage was fully absorbed within two days by the ~10% spare assembly capacity, which is a valid finding but not a "major" breakdown. — Shorter outage.
- **D-028 Vehicle breakdowns are fixed by field service (no technician walk); machine and conveyor repairs need the shift technician.** — Avoids routing technicians to mid-aisle positions; keeps technician contention on the equipment that matters. — Technician for everything.
- **D-029 A worker is marked on-break before coverage is requested.** — Architecture review found the floater re-claiming the station it just left and staying stranded after its break (29 of 30 days affected). Regression test in `workforce.test.ts`. — Clearing `coverTarget` after the walk.
- **D-030 Timed incident effects are owned by the latest incident of that kind.** — Overlapping spikes or slowdowns of the same kind used to be cancelled by the first one to end. — Reference counting.
- **D-031 A staffing change mid-phase banks the work done and continues at the new rate; phase progress stays continuous (a virtual start time).** — Assembly and inspection must stop at zero staff; animations must not jump. — Applying the change only at the next phase.
- **D-032 Failed conveyors freeze completely (no hand-off of the head item); repair re-offers the head.** — Spec: items freeze. — Letting downstream drain the head.
- **D-033 Vehicle utilisation = (travel with task + load/unload + queued) / (time not off-shift or failed), in both the dashboard and the inspector.** — The two views used to disagree. — Busy over plant open time.
- **D-034 Station state is also shown as a floor halo coloured by state (shared materials, a few draw calls).** — Stack lights alone are unreadable from the overview camera. — Bigger beacons.
