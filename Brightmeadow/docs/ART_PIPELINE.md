# Art Pipeline (3D models)

Every model in `game/assets/models/` is generated by Blender Python. Nothing is modelled by hand,
and there are no image textures. `docs/ASSET_CONTRACT.md` is the spec: file names, sizes, pivots,
palette, bones, animations and the manifest format.

## Regenerating

```bash
scripts/generate_models.sh            # build every GLB + manifest.json, then validate (~10 s)
scripts/generate_models.sh --render   # also render previews into assets/blender/renders (~6-7 min)
python3 assets/blender/validate_glb.py   # validation only (plain Python, no Blender needed)
```

The script sources `scripts/env.sh`. It then runs `assets/blender/build_all.py` in one of two ways:

- **Linux, bpy module (default):** `$BLENDER_PY` (`.tools/venv/bin/python`, which has the Blender
  4.5 LTS `bpy` wheel) runs the scripts directly. Renders run under `xvfb-run -a`. EEVEE works
  through Mesa llvmpipe.
- **macOS, or any machine with a real Blender 4.5:** set `BLENDER` and the script runs
  `blender -b --factory-startup --python <script> -- <args>`:
  ```bash
  BLENDER=/Applications/Blender.app/Contents/MacOS/Blender scripts/generate_models.sh --render
  ```
  Every script parses its arguments after `--` when that is present. Each script also adds its own
  folder and `lib/` to `sys.path`, so the same files work in both modes.

You can also run a single group, for example
`.tools/venv/bin/python assets/blender/gen_character.py` or
`blender -b --python assets/blender/gen_terrain.py -- --only ground_mid_a`. Running one group does
not refresh `manifest.json`; run `build_all.py`, or the shell script, to do that.

Output is deterministic. Seeds are fixed, nothing depends on time or file order, and two
consecutive builds give byte-identical GLBs. Builds are idempotent: each group starts from
`read_factory_settings(use_empty=True)` and overwrites its outputs.

## Layout

```
assets/blender/
  lib/
    common.py     bootstrap: paths, CLI args (after `--`), scene reset, .blend saving
    palette.py    the M_* palette materials (sRGB hex -> linear Principled BSDF), get_material()
    geom.py       bmesh shape library + MeshBuilder (see below)
    rig.py        armature building, binding, per-frame procedural actions, easing helpers
    export.py     GLB export with the fixed settings below; manifest writer
    glb.py        dependency-free GLB reader (bounds with skinning, triangles, animations)
    render.py     preview lighting / camera / ground helpers
  gen_character.py   explorer.glb (Juni): model, rig, 8 animations
  gen_enemies.py     bramblebug.glb, buzzpuff.glb
  gen_pickups.py     coin.glb, checkpoint.glb (Post + Flag), goal.glb (Arch + Emblem)
  gen_terrain.py     ground_mid_a/b/c, ground_cap_left/right, float_mid_a/b, float_cap_left/right
  gen_decor.py       trees, bush, flowers, grass_tuft, rock, mushroom, fence, signpost, hills, clouds
  build_all.py       runs every group, writes game/assets/models/manifest.json
  validate_glb.py    contract checks -> PASS/FAIL table, exit 1 on failure
  render_previews.py preview PNGs, rendered from the exported GLBs (so they test the exports too)
  source/<group>.blend  saved sources (compressed): character, enemies, pickups, terrain, decor
  renders/*.png         one per asset + lineup.png, explorer_poses.png, terrain_*_strip.png
```

### How models are built

- **Shapes** (`geom.py`) are bmesh primitives shaped in code. They include quad-spheres and
  superellipsoids with deformation callbacks (`blob`), Catmull-Rom swept tubes with tapering,
  elliptical sections, twist and round/pointed caps (`tube`), superellipse lofts (`loft`), lathes,
  tori and beveled extrusions. Blender modifiers (Bevel, Subdivision) are applied through a
  temporary object (`apply_modifiers`). `Surface` ray-casts onto a shape so details such as eyes,
  brows, straps, the zip, spots and the hair cap sit exactly on curved surfaces.
- **MeshBuilder** merges every part into a single mesh per object and gives each part a palette
  material. Parts are either rigidly skinned (weight 1.0 to one bone) or given a weight function
  (smooth blends at the torso, elbows and knees). Each mesh object gets a Weighted Normal modifier
  (keep sharp), and the exporter applies it. Hard edges are marked sharp by angle.
- **Rigs and animation** (`rig.py`): poses are authored per frame as Python functions, in armature
  axes (`BoneXf` rotation/location/scale). `to_basis` converts them to each bone's rest frame.
  `make_action` keys **every bone on every frame** (0..N), so each action is self-contained. It then
  stashes the action on its own muted NLA track and resets the pose, so the rest pose in the file
  is untouched. The character's legs use a two-bone sagittal IK (`Pose.leg`) that plants the boots
  and lifts the ankle when a pitched boot would sink into the ground. Follow-through on the hair,
  scarf and pack comes from phase-lagged copies of the body motion, plus extra bones (see
  deviations).

### Export settings (`lib/export.py`)

GLB, `export_yup=True`, `use_selection=True` (only the asset's own objects), `export_apply=True`
(modifiers applied, armature kept as a skin), materials embedded (`EXPORT`), no textures, UVs,
vertex colours, cameras or lights. Animations use `export_animation_mode='ACTIONS'` with
`export_anim_single_armature=False`, so only the actions on this armature's NLA tracks are exported.
Other settings: `export_force_sampling=True`, `export_reset_pose_bones=True`,
`export_optimize_animation_size=True`. The armature's active action is cleared and its pose reset
before export, so node transforms equal the rest pose.

**Frame counts:** an animation of N frames is keyed on frames 0..N, with frame N equal to frame 0
for loops. Its glTF duration is N/30 s (for example, `walk` = 24 frames = 0.8 s). The validator and
the manifest report `round(duration * 30)`.

## Terrain tiling

Each terrain piece is one edge profile (`GROUND_PROFILE` / `FLOAT_PROFILE`) swept along a plan
path:

- **Mids:** straight front and back edges.
- **Caps:** one U-shaped path around a rounded outer end.

The scalloped grass lip is driven by a sum of `(1 - cos(2*pi*k*u))/2` terms. The value and slope of
these terms are 0 at both ends of a mid and at a cap's inner edge. So every joint has exactly the
same cross-section in any order, and the shading matches across the seam. The walk surface is a
flat n-gon at y = 0 spanning the exact x extents. Grass tufts sit only at the back (|z| > 0.75),
away from the play line. Floating pieces get a rounded underside from rings that close toward the
centre line.

`validate_glb.py` checks this numerically on the exported files:

- The joint vertex sets at x = ±0.5 (mids) and x = 0 (caps) are identical (30 points for ground,
  29 for float).
- A vertical ray grid over |z| ≤ 0.5 finds the highest surface at exactly y = 0, across the full
  x span of each mid and the first 0.2 m from a cap's inner edge.

## Validation (`validate_glb.py`)

For each contracted file, the validator checks:

- the file exists
- triangle budget
- palette-only material names
- no cameras or lights
- size against the contract
- pivot (bottom-centre, centre, or terrain rules)
- explorer stays inside its capsule (r = 0.38) at rest
- required nodes (`Armature` and all contract bones, `Post`, `Flag`, `Emblem`)
- `Flag` origin at y = 2.1
- `Emblem` origin at its centre
- animation names and frame counts, with no unexpected animations
- the explorer's `root` never translates

It also checks terrain tiling (above), that `manifest.json` matches the files, and that the models
folder is under 15 MB (it is about 2 MB).

## Preview renders

`render_previews.py` imports each GLB into a fresh scene and renders it with EEVEE Next (16
samples). Every render uses the same palette lighting: a warm key sun from the front-left, a cool
rim sun, a sky-blue world, the Standard view transform and a soft ground disc.

| Render | Contents |
|---|---|
| `lineup.png` | explorer, bramblebug, buzzpuff and coin |
| `explorer_poses.png` | 8 rows (one per animation) × 5 frames, profile view as in game, labelled |
| `terrain_ground_strip.png`, `terrain_float_strip.png` | caps and mids tiled |

## Known deviations from the contract

- **Extra explorer bones:** `hair`, `scarf.1`, `scarf.2`, `eye.L`, `eye.R`. They drive the
  follow-through on the hair tuft and scarf tails, and blinks / squints (the eyes scale shut). All
  contract bones exist with the contract names, so this is a superset.
- **Enemy rigs:** the enemies also use an armature named `Armature`. Bramblebug bones: `root`,
  `body`, `head`, `sprout`, `leg.L.0-2`, `leg.R.0-2`. Buzzpuff bones: `root`, `body`, `wing.L/R`,
  `antenna.L/R`. Bramblebug has the optional `idle` (40 frames) as well as `walk`.
- **Buzzpuff wings** use `M_Wing` as specified (opaque, rough 0.3) with a white `M_FlowerWhite`
  rim. They read as pale and light but are not alpha-blended. That avoids transparency sorting in
  Godot; set the material's transparency Godot-side if real translucency is wanted.
- **Extra materials:**
  - Mittens use `M_Scarf` (they match the scarf).
  - Bramblebug's iris uses `M_FlowerYellow` ("yellow-white eyes").
  - The mushroom uses `M_Scarf` and `M_FlowerWhite`.
  - The goal bunting alternates `M_Banner`, `M_FlowerYellow`, `M_Jacket` and `M_FlowerPink`.

  All of these are palette materials; no new materials were added.
- **Cap walk surface:** caps have a rounded outer edge. Their flat walk surface runs from the inner
  edge to about 0.27 m out; beyond that the top rounds down over the lip, which still ends exactly at
  x = ∓0.5.
