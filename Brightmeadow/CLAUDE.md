# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Brightmeadow ("Juni's Trail") is an original 2.5D side-scrolling platformer: Godot 4.5.1 +
GDScript, with every 3D model generated by Blender Python and all audio synthesised in Python.
`README.md` covers setup, running, controls and export; `docs/` holds architecture, the asset
contract, level design, pipelines and the progress log.

## Commands

Run from this `Brightmeadow/` folder. Tools come from `scripts/setup_linux.sh` (into `.tools/`);
`scripts/env.sh` resolves `$GODOT` and `$BLENDER_PY` (override either via the environment).

```bash
scripts/setup_linux.sh [--templates]      # install Godot 4.5.1 + bpy 4.5 LTS venv (+ export templates)
scripts/validate.sh [--shots]             # asset checks, import, all tests, boot (+ screenshots)
source scripts/env.sh
$GODOT --headless --path game --import    # refresh imports and the class_name cache (do this first)
$GODOT --headless --fixed-fps 60 --path game res://tests/run_tests.tscn                    # all tests
$GODOT --headless --fixed-fps 60 --path game res://tests/run_tests.tscn -- --filter=smoke  # one file
scripts/generate_models.sh [--render]     # rebuild GLBs from assets/blender (+ preview renders)
scripts/generate_audio.sh                 # rebuild audio
scripts/screenshots.sh [x,x,...]          # Forward+ screenshots via Xvfb into tests/output/shots
scripts/export.sh [macos|linux]           # release builds into build/
```

## Key Rules

- **All movement tuning lives in `game/resources/movement_default.tres`** (`MovementConfig`).
  Don't hard-code movement numbers elsewhere. After changing it, run the tests: the feasibility
  test and autoplay bot re-check the level against the new numbers.
- **`MovementModel` must match the controller.** `Player` uses its functions every step; the
  smoke test compares real jump height to the model. Keep them in lock-step.
- **Physics and visuals stay separate.** Never scale/rotate the `Player` body or its collision;
  presentation changes go on `PlayerVisual` (pivot at the feet), on physics ticks.
- **Models are referenced by contract name** through `ModelLib`. Names, pivots, node names and
  animation names are fixed by `docs/ASSET_CONTRACT.md`; change the contract first.
- **Level edits go in `game/levels/level_01.json`** (whole-number widths ≥ 2 so terrain tiles).
  Run the feasibility test after any change.
- New `class_name` scripts need a `--import` run before headless tests can see them.
- Gameplay is on z = 0. Physics layers: world 1, player 2, enemy hitboxes 4, triggers 8.
